## ADR-0001 — تغيير المنصة التقنية: FastAPI بدل ASP.NET Core ⚠️ (انحراف عن ملف 01)

- **التاريخ:** 2026-08-04
- **الحالة:** معتمد
- **السياق:** ملف 01 (SYSTEM_ARCHITECTURE) حدد .NET 8 + SQL Server/PostgreSQL. بيئة
  التطوير المتاحة (Arena Sandbox) لا تحتوي .NET SDK ولا SQL Server، وتعذّر تثبيتهما
  (مستودعات التوزيعة معطلة، وشبكة CDN الخاصة بمايكروسوفت محجوبة). المتاح: Python 3.11،
  Node 22، SQLite، مع إمكانية استهداف PostgreSQL في الإنتاج.
- **القرار:** بناء الخادم بـ **Python 3.11 + FastAPI + SQLAlchemy 2** مع نفس العقود:
  - الواجهات API بنفس المسارات والأكواد المنصوصة في ملف 12 (API_STRUCTURE).
  - قاعدة البيانات: SQLite للتطوير/التركيب المحلي الصغير، PostgreSQL للإنتاج السحابي —
    عبر `DATABASE_URL` واحدة دون تغيير كود.
  - الواجهة: React 18 + TypeScript + Vite + Tailwind (كما في ملف 01).
- **العواقب:** لا تغيير في أي قاعدة محاسبية (ملف 02 مرجع ملزم حرفياً). الحزم: الصلاحيات،
  التدقيق، الترقيم، Idempotency كلها مطبقة كما نصت الوثائق. قرار التقنية قابل للمراجعة
  عند توفر بيئة .NET — المعمارية طبقية والمنطق منعزل في `posting.py` وحدها (~300 سطر).
- **البدائل المرفوضة:** التأجيل حتى توفر .NET (يخالف توجيه "البناء مقدّم")، Node/Express
  (ضعف معاملات المحاسبة الذرية مقارنة بجلسة SQLAlchemy المتزامنة).

## ADR-0002 — الانتقال الوحيد المسموح على القيد المرحَّل: وسم REVERSED

- **التاريخ:** 2026-08-04 · **الحالة:** معتمد
- **السياق:** ملف 02 يمنع أي UPDATE على القيد المرحَّل. لكن العكس يحتاج دلالة تمنع
  العكس المزدوج وتربط الأصل بعكسه.
- **القرار:** يُسمح حصراً بتحديث حقول الحالة: `status: POSTED → REVERSED` وربط
  `reversed_entry_id` على القيد الأصلي عند إنشاء قيد العكس. أي تحديث آخر لأي حقل مالي
  أو تاريخي في قيدٍ حالته POSTED/REVERSED ممنوع برمجياً (حارس `ensure_not_mutating_posted`)
  وممنوع صراحةً في الإنتاج عبر REVOKE UPDATE + Trigger (خطة النشر).
- **التبرير:** العملية الوحيدة التي تكتب على المرحَّل هي العكس نفسه — دالة واحدة مركزية
  `reverse_entry()`؛ لا توجد نقطة API للتعديل أو الحذف أصلاً (مختبَر).

## ADR-0003 — تجزئة JWT: HS256 بدل RS256

- **التاريخ:** 2026-08-04 · **الحالة:** معتمد (مؤقت لوضع Local)
- **السياق:** ملف 10 نص على RS256. في وضع On-Premise أحادي الخادم، مفتاح سري مشترك
  كافٍ وأسهل تشغيلياً (لا PKI).
- **القرار:** HS256 في وضع `local`؛ عند تفعيل وضع `cloud` يُفرض RS256 (خطة المرحلة
  الخاصة بلوحة البائع). طول السر ≥ 32 بايت يُتحقق منه عند الإقلاع في وضع cloud.

## ADR-0004 — جداول SQLite للتطوير: Unicode وحقول JSON

- **التاريخ:** 2026-08-04 · **الحالة:** معتمد
- **السياق:** ملف 11 حدد JSONB/PostgreSQL. SQLite لا يملك JSONB.
- **القرار:** حقل JSON عام عبر `JSON` type مع محوّل مستقبلي إلى `JSONB` عند
  `postgresql://` (SQLAlchemy TypeDecorator). فروقات DDL الأخرى (الفهارس الجزئية،
  RLS) موثقة كمهام نشر إنتاج وليست كود تطوير.

## ADR-0005 — سجل التدقيق: تطبيع التواقيت إلى UTC قبل التجزئة

- **التاريخ:** 2026-08-04 · **الحالة:** معتمد
- **السبب:** SQLite يقرأ DateTime(timezone=True) بلا منطقة زمنية؛ اختلاف تمثيل
  isoformat كسر سلسلة التجزئة عند التحقق. القرار: تطبيع كل الطوابع الزمنية naive←UTC
  داخل `canonical_hash` لضمان تطابق التجزئة قبل/بعد التخزين على كل القواعد.
