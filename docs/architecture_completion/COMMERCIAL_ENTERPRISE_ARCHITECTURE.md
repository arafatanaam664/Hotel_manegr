## 1. المبادئ الحاكمة (القواعد الـ20 + قرارات الفريق)
1. **البيع هو البنية:** كل قيد تجاري (خطة/نسخة/وحدة/حد) يُفرض خادمياً من الحمولة الموقّعة أو قناة التحكم — وليس من الواجهة ولا من جداول قابلة للتعديل من العميل.
2. **المحلي أولاً:** ON-PREM وHYBRID يعملان بلا إنترنت إلى الأبد التشغيلي؛ السحابة طبقة قيمة مضافة لا شرط تشغيل.
3. **خصوصية العميل افتراضياً:** لا بيانات أعمال تغادر الفندق إلا بعقد صريح (نسخ مشفر فقط)؛ الشركة ترى **تعريفات ووصايات no بيانات تشغيلية**.
4. **بيانات التجربة مقدسة:** لا حذف عند انتهاء TRIAL؛ التحويل لمدفوع = تبديل حمولة موقعة فقط، صفر لمس للبيانات.
5. **كل فعل حساس موقَّع:** تفعيل/تعليق/تجديد/تمديد/تغيير نشر/استعادة/تحديث — حدث تدقيقي بجانبَيه (شركة+فندق).
6. **قابلية الآلاف:** كل قرار هنا يُفحص بسؤال «هل ينجح مع 10,000 فندق؟».

## 2. نموذج النشر الثلاثي الرسمي (Deployment Profiles) — المتطلب 1

| البعد | A — ON_PREM | B — CLOUD | C — HYBRID (الهوية) |
|---|---|---|---|
| مقر التطبيق+القاعدة | خادم الفندق | سحابة الشركة (متعدد المستأجرين) | خادم الفندق + طبقة سحابية |
| العمل بلا إنترنت | **كامل** | لا (تعاقدياً متصل) | **كامل** |
| الترخيص | تحقق دون اتصال (موقّع+مرساة) | تحقق لحظي | موقّع دون اتصال + نبض عند التوفر |
| النسخ | محلي مشفر إلزامي | سحابي مُدار | محلي + سحابي مشفر (إن تعاقد) |
| المزامنة | قناة USB/يدوية فقط | غير مطلوبة (قاعدة مركزية) | Outbox/Inbox كاملة |
| التحديثات | حزمة موقعة بمعالج بصري (+USB) | فوري من الشركة | موقعة+delta مرنة |
| مناسب لـ | فنادق بلا بنية اتصال/سيادية | سلاسل صغيرة متصلة | **الغالبية اليمنية** |

**القرارات المُلزمة:**
- نوع النشر **ليس Setting بالواجهة** — هو رباعية: `DeploymentProfile` (كيان) × حقل `deployment_type` داخل الحمولة الموقّعة × `Customer Configuration` (قناة التحكم) × `Infrastructure` (تثبيت). تغييره = فعل شركة بصلاحية Vendor `deploy.change` مع **سير نقل بيانات موثق** (تصدير موقّع → تحقق → استيراد → تحقق مطابقة → إشهار تحول — حدثان متطابقان بالجانبين).
- السحابي متعدد المستأجرين بعزل صفّي صارم (tenant_id بكل صف ✅ قائم) مع **قرار معماري مؤجل**: schema-per-tenant عند أول 50 مستأجر سحابي إن طلبه الأداء/التنظيم (ADR لاحق — انظر CHANGE_PLAN §P).
- HYBRID تعريفياً يلزمه CLOUD_SYNC=مفعّل (رسم الاعتماديات في FEATURE_ENTITLEMENT §I).

│     └── LicensePayload v2: license_id, customer_id, tenant_id, edition, plan_code,
│         deployment_type, modules_enabled[], features_flags{}, limits{max_users,max_branches},
│         trial{trial:true, started, ends, extensions_allowed}, issued_at, valid_until, grace_until,

├── Subscription (سجل VND: خطة/فترة/فواتير/تحصيلات) — يربط Plan↔Customer↔License
├── Edition ↔ FeatureSet (ملف تعريف مزايا — كود/اسم/حدود) K → ينتج modules+flags الافتراضية
├── FeatureEntitlement (Effective = Edition × Plan × License overrides) — مصدر الحقيقة للواجهة/الواجهات البرمجية
├── Configuration (3 طبقات ملكية: SYSTEM_IMMUTABLE / COMPANY_ONLY / HOTEL+USER) — J
├── BackupPolicy → BackupJob → RestoreTest  (H — وثيقة BACKUP)

## 4. آلات الحالات (D) — 7 آلات رسمية

### 4.1 الترخيص (الموجود — الحقيقة من الكود، 8 حالات)
`TRIAL → LICENSED → GRACE → READ_ONLY → SUSPENDED` · نهائيات/أخطاء: `REVOKED · INVALID · CLOCK_LOCK`.
- انتقالات: تقييم عند الإقلاع+المجدول+النبض · GRACE أيامها داخل الحمولة · READ_ONLY يسمح قراءة/تصدير ويمنع كتابة أعمال · SUSPENDED بقرار شركة موثق مع **حساب طوارئ مالي** (تصدير فقط) ✅ · REVOKED بقائمة إبطال بسريال تصاعدي (heartbeat/USB) · CLOCK_LOCK عند رجوع ساعة >يوم ✅.
- أيام التنبيه قبل الانتهاء: 30/15/7/3/1 (ربط NTF-SYS-04).

### 4.2 التجربة Trial (باطن حالة TRIAL — جديد كسمة فرعية)
`TRIAL_ACTIVE → TRIAL_WARNING(≥7 أيام متبقية) → TRIAL_EXPIRED → CONVERTED` · فرع: `EXTENDED` (رزمة تمديد موقعة من الشركة تدفع ends فقط).
- TRIAL_EXPIRED ≠ حذف: واجهة انتهاء كاملة (إشعار/تاريخ/قناة تواصل/حقل License Key/زر تفعيل) مع قراءة كاملة للبيانات وتجميد الكتابة (مثل READ_ONLY).

### 4.3 الاشتراك Subscription (جهة الشركة)
`DRAFT → ACTIVE → PAST_DUE → SUSPENDED → EXPIRED | RENEWED → …` — فوترة دورية ✅ موجودة (run-cycle) + تحصيلات ✅؛ الجديد: ربط آلي بحالة الترخيص (PAST_DUE≥N يوم ⇒ إصدار قرار GRACE/SUSPEND وفق سياسة مدروسة — بشري القرار، آلي الإنفاذ).

### 4.4 النشر Deployment
`PLANNED → PROVISIONING → INSTALLED → ACTIVATING → ACTIVE → MIGRATING? → DECOMMISSIONED` — كل انتقال خطوة موثقة بـProvisioningRun؛ ACTIVE شرطه فحوص الإقلاع خضراء (ترخيص+نسخ+مزامنة إن HYBRID).

### 4.5 النسخ Backup
`SCHEDULED → RUNNING → STORED → VERIFIED` / فشل: `FAILED → ALERTED` (NTF-SYS-03 P1-حرجة) · `VERIFIED` شرطه فحص فتح فعلي (لا وجود ملف فقط) · اختبار الاستعادة الدوري آلة مستقلة: `RESTORE_TEST_{SCHEDULED,RUNNING,PASSED,FAILED}`.

### 4.6 المزامنة Sync (الموجود + رسمة)
`UNPAIRED → PAIRED → SYNCING → HEALTHY | LAGGING → CONFLICTED → RECOVERING → HEALTHY` · `SEVERED` (فك اقتران موثق). معلّق=فشل نقل؛ LAGGING عتبة عمر/عدد؛ CONFLICTED يدخل صندوقاً بشرياً ✅؛ RECOVERING=استدراك/backfill آلي ✅.

### 4.7 التحديث Update
`DETECTED → STAGED → BACKED_UP → APPLYING → HEALTH_CHECKED → DONE` / `FAILED → ROLLED_BACK` (نسخة ما قبل التحديث+حزمة سابقة) — لا DONE بلا Health Check، ولا تطبيق بلا BACKED_UP (قاعدة صلبة).

## 6. مركز التحكم بالشركة (Company Control Plane — المتطلب 14)
توسعة لوحة VND الموجودة (7 شاشات ✅) بمقطع «ملف العميل 360°» (SCR-VND-009 مصمم سابقاً) ليعرض بطاقة كما في نموذج المستخدم حرفياً: Deployment/Plan/Version/Modules ✓✗/Users x/y/Branches/Last Backup/Last Sync/Health/License Expiry — كلها **ميتاداتا النبض** المتوفرة حالياً (heartbeat يرسل إصدار/حالة مزامنة/عدادات ✅) + إضافة حقول نبض جديدة: آخر نسخة موفقة/نتيجة اختبار استعادة/عدد مستخدمين فعلي. **لا تخزن السحابة أي محتوى تجاري** — طابعة خصوصية §11.
أقسام جديدة: قمع التجارب (Trial Funnel)، جدولة التحديثات بقنوات، سجل التفعيلات، لوحة صحة مجمعة (موجودة جزئياً)، RPT-VND-002 MRR/Churn.

## 7. قابلية التوسع 1→10,000 فندق
- الحافة: خادم بلا حالة مشاركة بين الفنادق — قابلية لا نهائية بنيوياً ✅.
- المركز: VND على PostgreSQL؛ فهارس نبض/ترخيص؛ تجميع MRR daily rollups (لا استعلامات خام على الجداول الحية)؛ قنوات الإصدار تدحرجية (канар 5% → موجات).
- النبض يخفف بالبصمة/التغييرات (دارسة بالخادم) + Backoff بإزاحة عشوائية لمنع «قطيع النبض» ✅ منطق موجود بالمزامنة — يُعمّم.
- قاعدة التوسع الذهبية: **لا JOIN بين مستأجرين أبداً في طريق الحرارة؛ التقارير المركزية من تجميعات فقط**.

## 9. مراجعة الأمن المعمارية (المتطلب 26) — الحكم المختصر
موجود وقابل للإثبات: عزل صفّي بكل استعلام عبر Principal إلزامي ✅، قفل/نوافذ/إبطال جلسات ✅، تشفير PII ساكن ✅، سلسلة تدقيق ✅، توقيع ترخيص+بصمة+مرساة ساعة ✅، MFA لوحة الشركة ✅، رسائل خطأ معيارية بلا تسريب ✅، ORM معاملات (لا SQL خام مكشوف) ✅.
