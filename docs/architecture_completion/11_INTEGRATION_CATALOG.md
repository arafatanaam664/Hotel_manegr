# 11 — كتالوج التكاملات (Integration Catalog)

> **المرحلة الثانية — تصميم فقط.** ✅ جزئياً موجود (USB/مزامنة/NTP) · 🆕 مصمَّم هنا.
> **قرار معماري حاكم — نمط المحوّل الموحد (Adapter Ring):** لا تكامل يُكتب داخل الوحدات؛ كل تكامل خلف واجهة موحدة: `connect / status / push / pull / webhook-in / map-errors`. الأسرار بخزنة مشفرة، كل تكامل Feature-Flag بملف الترخيص، الواردة عبر خطافات Idempotent، والصادرة عبر Outbox نفسه. المحوّل المعطّل **لا يوقف العمل المحلي أبداً** (درس R4).

## قواعد بنيوية لكل تكامل
1. **Fail-Open للتشغيل، Fail-Closed للأمن:** انقطاع القناة لا يوقف الفرونت؛ فشل توقيع/تصديق يوقف التبادل ويُخطر.
2. **خصوصية أولاً:** لا تُرسل PII مشفرة-ساكنة إلا مفككة لحظياً وللغرض فقط (درس المعلومية).
3. عدّادات صحة لكل محوّل تظهر بلوحة الصحة SCR-MON-001 (حالة/آخر نجاح/أخطاء 24س).
4. كل Webhook وارد له: توقيع تحقق + إعادة تشغيل آمنة + شاشة فحص بمركز المزامنة.
5. **الأولويات:** P0=ساعة/NTP+USB تخزين؛ P1=طابعات/باركود؟(P2)/بريد/QR/تصدير محاسبي؛ P2=واتساب/SMS؛ P3+=OTA/دفع/BI… (كلها معللة أعلاه).
