## 4. آلة حالات الترخيص الثمانية — جدول الانتقالات التشغيلي
| الحدث | من → إلى | الأثر التشغيلي |
|---|---|---|
| أول تشغيل بلا ترخيص | — → TRIAL | كامل المزايا المشمولة بالتجربة؛ بدء عدّاد العميل |
| انتهاء مدة التجربة | TRIAL → GRACE(إن ضبطت) أو READ_ONLY | تنبيه 30/15/7/3/1 قبلها؛ بعدها كتابة مجمّدة + قراءة/تصدير كاملان |
| تثبيت ملف تفعيل صالح | * → LICENSED | صفر لمس للبيانات (قاعدة 4)؛ الحدود الجديدة تسري فوراً |
| انقضاء valid_until بلا تجديد | LICENSED → GRACE | تشغيل كامل + بانر تجديد بارز + إشعار شركة |
| انقضاء المهلة | GRACE → READ_ONLY | قراءة/تصدير/تقارير؛ منع كتابة أعمال (LIC.READ_ONLY) |
| قرار شركة موثق (شخصان) | GRACE/READ_ONLY → SUSPENDED | منع دخول عمليات؛ حساب الطوارئ المالي يصدّر؛ لا تلقائي أبداً |
| سريال إبطال أعلى | * → REVOKED | قراءة/تصدير فقط؛ سبب إلزامي؛ قابل للرفع بإصدار جديد |
| توقيع مكسور/ملف فاسد/مستأجر مخطئ | * → INVALID | لا يعتمد الملف؛ الحالة السابقة تبقى حاكمة حتى ملف صالح |
| رجوع ساعة > يوم | * → CLOCK_LOCK | توقف احترازي + رسالة ضبط التاريخ؛ يُفك بملف صالح بعد تصحيح الساعة |
| انتهاء تجربة نهائي | TRIAL_EXPIRED (داخل READ_ONLY) | واجهة G §5 — بيانات محفوظة كاملة |

## 5. سير التجربة الكامل (المخرَج G) — المتطلب 16
**القاعدة المقدسة: لا حذف لبيانات التجربة أبداً؛ التحويل لمدفوع = تبديل حمولة موقعة فقط.**

| المرحلة | ما يحدث | الواجهة/النظام |
|---|---|---|
| **1. إنشاء Trial** | الشركة تنشئ العميل (VND) وتصدر حمولة `edition=TRIAL` بمدة/حدود الخطة المستهدفة؛ التجربة ليست «تثبيتاً يتيمًا» بل قيد عميل قابل للمتابعة | vendor: إصدار ترخيص ✅ + إضافة حقول الحمولة v2 |
| **2. التهيئة** | معالج الإعداد 28 خطوة (DEPLOYMENT §4)؛ بيانات الفندق **حقيقية منذ اليوم الأول** | WIZ-001 الموسع |
| **3. الاستخدام** | تشغيل كامل للمزايا المشمولة؛ شريط علوي دائم: «تجربة — تبقى N يوماً» + عدّاد استخدام الميزات للاحق البيعي | SCR-CMR-003 (مكوّن ترويسة) |
| **4. التحذير** | عند 14/7/3/1: بانر متصاعد + إشعار مالك + بطاقة «جاهز للتحويل؟» بقناة التواصل؛ الشركة ترى قمع التجارب | NTF-SYS-04 معمّم + VND-CMR-001 |
| **5. الانتهاء TRIAL_EXPIRED** | **ليست نهاية عالم:** شاشة كاملة تعرض — إشعار «انتهت تجربتك. بياناتك كاملة ومحفوظة» — تاريخ الانتهاء — قناة تواصل الشركة — **حقل إدخال License Key / زر رفع ملف** — زر «طلب تمديد»؛ النظام يدخل READ_ONLY: كل الشاشات تقرأ، التصدير يعمل، الكتابة مجمّدة | SCR-CMR-008 + حالة READ_ONLY ✅ |
| **6. التفعيل → مدفوع** | إدخال مفتاح/ملف → تحقق توقيع+بصمة → `LICENSED` فوري؛ **صفر فقدان بيانات، صفر إعادة إعداد، صفر توقف يتجاوز لحظات** | `license/install` ✅ |
| فرع **التمديد** | الشركة تصدر **رزمة EXTENDED موقعة** تدفع `trial.ends` فقط (لا حدود أخرى تتغير)؛ يجب `extensions_allowed>0` بالحمولة؛ كل تمديد حدث تدقيقي بالجانبين وسريال أعلى | LIC §3 + CHANGE §N |

**ضد الإساءة (CR-02):** بصمة الجهاز معروفة لدى الشركة؛ تثبيت جديد على جهاز سبقت تجربته بلا إصدار شرعي جديد = `TRIAL_EXPIRED` لحظياً (الشركة لم تُصدر trial لهذه البصمة). «لا حذف للبيانات» ≠ «تجربة متجددة».

## 6. سير التفعيل (المتطلب 19) — متصل ودون اتصال
1. **طلب التفعيل:** النظام يولّد `activation-request` (tenant_id + بصمة + إصدار) ✅ موجود — يُعرض كملف/نص/QR.
2. **الاعتماد بالشركة:** مشغل التراخيص يراجع (عميل قائم؟ خطة مدفوعة/مصدَّقة؟ بصمة جديدة = FingerprintAlert؟) → يصدر.
3. **التسليم بمسارين:**
   - **ملف موقّع** (الموجود ✅) — USB/بريد؛ يُثبَّت بـ`license/install`؛ دون اتصال بالكامل.
   - **مفتاح قصير إنساني** 🆕: `XXXX-XXXX-XXXX-XXXX` (≈80bit + تحقق داخلي) مشتق حتمياً من (license_id + بصمة + serial) — يعمل **فقط** على الجهاز/المستأجر المقصود، يستهلك serial تصاعدياً، ويُملي الحمولة الموسّعة؛ للفنادق المعزولة هاتفياً (إملاء صوتي).
4. **فشل التفعيل لا يعاقب:** ملف مكسور = INVALID للملف فقط؛ الحالة السابقة تحكم حتى ملف صالح (§4).

## 7. التحقق دون اتصال (المتطلب 21) — عقيدة العمل المعزول
1. التحقق توقيع محلي بالمفتاح العام المضمّن ✅ — لا يتصل بشيء.
2. مرساة الساعة الرتيبة: آخر تاريخ عمل معروف يتقدم فقط؛ رجوع>يوم = CLOCK_LOCK ✅.
3. GRACE محسوبة داخل الحمولة (grace_until) — لا تستحق من الشركة ✅.
4. الإبطال يصل عبر نبض **أو USB** رسمي مع سريال تصاعدي ✅ (`sync/import-usb` + pull-licenses).
5. النبض **ليس شرط تشغيل** (قاعدة MASTER-2)؛ غيابه الطويل = تذكرة دعم وعلامة صحة باللوحة — لا قفل آلي (T-09).
6. حدود (مستخدمون/فروع/وحدات/قدرات) كلها من الحمولة المحلية الموقعة — تعمل بمعزل تام ✅.

## 8. التجديد (المتطلب 22) — سير نهاية-لنهاية
`تنبيه 30/15/7/3/1 (بانر+بريد+بطاقة VND) → فاتورة تجديد دورية ✅ (SubscriptionInvoice kind=RENEWAL) → تحصيل ✅ (Collection) → مشغل يصدر حمولة جديدة valid_until ممدد → تسليم قناة/ملف → LICENSED من جديد بلا انقطاع`. قرار سياسي معلّق للمالك: **هل PAST_DUE≥N يوماً يقود GRACE→READ_ONLY آلياً؟** توصية الفريق: نعم للـREAD_ONLY فقط، والإيقاف يبقى بشرياً مزدوج التوثيق (§4).

## 9. تمديد التجربة — آلية EXTENDED
يُدار كرزمة موقعة مستقلة `{type:'TRIAL_EXTENSION', license_id, new_ends, serial, signature}`: تُقبل فقط إن `serial` أعلى، و`extensions_allowed` لم يُستنفد، والبصمة/المستأجر يطابقان؛ تُسجل `license_events` (CHANGE §M) بالجانبين؛ حد أقصى افتراضي: تمديدان × 14 يوماً (يضبطهما قرار تجاري بالحمولة).

## 10. تفعيل/تعطيل ميزة من الشركة (المتطلب 18) — قناة رسمية
1. طلب العميل (من صفحة مقفلة §FEATURE-5) أو قرار شركة → تذكرة اعتماد.
2. محرر النسخ/القدرات (VND-CMR-003) يعدّل feature_set/overrides → **مدقق الاعتماديات I يرفض المجموعات المكسورة قبل الإصدار** (مثلاً: تعطيل ACCOUNTING مع HOTEL قائم).
3. إصدار حمولة v2 جديدة (serial أعلى) → تسليم بقناة التحكم (sync control — D-3) أو ملف.
4. التطبيق لدى الفندق: تحقق توقيع ← تسجيل حدث ← **إشعار واجهة للمالك بما تغيّر** ← الإنفاذ الخادمي فوري.
تعطيل ميزة عليها بيانات قائمة لا يحذف شيئاً: تصبح قراءة-فقط بالسجل مع بوابة «سبب التعطيل».

| T-07 | سرقة ملف قاعدة البيانات كاملة | PII مشفرة ساكناً ✅؛ النسخ الاحتياطية AES-256-GCM بمفتاح عميل (BACKUP §2) | مفاتيح لكل عميل ⇒ تسرب جهة لا يعمّم؛ تدوير مفاتيح موثق |
| T-08 | انتحال قناة تحكم/رسالة إبطال مزيفة | كل رزمة موقعة + سريال تصاعدي؛ القديم/المخترق مرفوض ✅ | LIC.OLD_SERIAL/OLD_REVOCATION + تدقيق |
| T-09 | عزل الفندق عن الشبكة للتهرب من التوقيف | تصميم مقصود: التشغيل المحلي لا يتوقف بالعزل (قاعدة 2) — والإيقاف ليس آلي العزل أصلاً | سريال الإبطال يصل بالنبض عند عودته **أو USB رسمي**؛ وثيقة «آخر اتصال» بالسجل التجاري؛ القرار بشري (§4) — مقايضة معلنة: لا نعاقب التشغيل الشرعي المعزول |
| T-10 | مشاركة مفتاح التفعيل القصير | مربوط بصمة+مستأجر+serial يُستهلك ✅ التصميم §6 | إعادة استعمال = OLD_SERIAL؛ إنذار بصمة |
| T-11 | اختراق مفتاح التوقيع الخاص (جهة الشركة!) — أخطر سيناريو | وقائي: حراسة مقسّمة/شخصان/تخزين HSM-مكافئ؛ تدوير `vendor_epoch` بالحمولة (CR-01) | خطة استجابة: epoch جديد + إبطال جماعي بسريال موجة + إعادة إصدار مدارة + تحقيق VendorAudit |
| T-12 | إساءة صلاحية دعم عن بعد لنقل ترخيص/بيانات | جلسات موافقة مقيدة نطاقاً وزماناً (DEPLOYMENT §8)؛ **جلسة الدعم بلا صلاحية ترخيص بنيوياً** | تدقيق كامل + إلغاء فوري بيد الفندق |

**الفلسفة المعلنة (تُكتب بالعقد):** الهدف حماية إيراد عادل وردع التلاعب النمطي، لا بناء قفل مطلق مستحيل؛ **القيمة التي لا تُنسخ هي التحديثات والدعم والسحابة والتكاملات** — فلا نعتمد على التعتيم، ونعتمد على التوقيع والمراقبة والعلاقة.
