================================================================================
08 — مواصفة لوحة تحكم الشركة المالكة (Vendor Control Panel Specification)
نظام أثير لإدارة الفنادق | الإصدار 1.0 | 2026-08-04
تطبيق مستقل بالكامل عن أنظمة العملاء — قلب الإيرادات وإدارة العلاقة التجارية
================================================================================

================================================================================
القسم 1 — المبادئ والعزل
================================================================================
- مستودع/نشر/نطاق مستقل (مثلاً: console.atheer.example)؛ قاعدة بيانات خاصة
  لا تشارك قاعدة عملاء؛ صلاحيات فريق الشركة فقط (أدوار: مدير، مبيعات، مالية،
  دعم L1، دعم L2، مشغّل تراخيص).
- تواصل الأنظمة العميلة معه عبر «واجهة العميل المحدودة» (Client Edge API):
  نبض+تحقق ترخيص، رفع/تنزيل مزامنة، فتح تذكرة، تنزيل تحديث — لا أكثر أبداً.
- مبدأ صفر ثقة عكسية: بيانات العميل التشغيلية (قيوده/نزلاؤه) لا تُخزَّن في
  لوحة الشركة إلا مجمَّعة للتقارير التعاقدية وبموافقة العقد (انظر SLA).

================================================================================
القسم 2 — إدارة العملاء (CRM تشغيلي)
================================================================================
ملف العميل: الاسم القانوني/التجاري، بيانات الاتصال والموقع، الفندق وعدد
الغرف، الفروع، قناة البيع، العقد (نسخة مرفقة)، الباقة (LOCAL/CLOUD/HYBRID)،
الوحدات المشتراة، تاريخ التفعيل، تاريخ الانتهاء، حالة الاشتراك:
  ACTIVE | TRIAL | GRACE | READ_ONLY | SUSPENDED | TERMINATED
سجل كامل زمني لكل تغيير حالة مع السبب والمستخدم.

================================================================================
القسم 3 — الاشتراكات والتحصيل
================================================================================
- خطط الأسعار (تُدار من PRICING_STRATEGY): رسوم تأسيس + اشتراك سنوي/شهري،
  أسعار لكل وحدة إضافية/مستخدم إضافي/فرع إضافي، خصومات (موسمية/كمية) بسقف
  اعتماد.
- دورة الفوترة: إنشاء فاتورة اشتراك (تذكير قبل 30/14/7 أيام من الانتهاء) ←
  تسجيل التحصيل (نقد/تحويل — إدخال يدوي موثق حالياً؛ بوابات الدفع مرحلة 2)
  ← توليد ترخيص مجدد آلياً بعد التحصيل ← تحديث الملف مرة واحدة.
- لوحة الإيراد: MRR/ARR، معدل التجديد (Renewal Rate)، Churn، عملاء متأخرون
  بأعمار التأخر، توزيع الباقات، إيراد متوقع 90 يوم.
- قواعد آلية: انتهاء بلا سداد ← GRACE (مهلة الترخيص) ← إشعار + مهمة مبيعات
  ← بعدها READ_ONLY تلقائياً عبر License Service (انظر ملف 07 §3).

================================================================================
القسم 4 — التراخيص (تكامل مع ملف 07)
================================================================================
شاشة مشغّل التراخيص: إصدار/تجديد/تعديل وحدات/رفع حدود/إيقاف/إلغاء، قائمة
الإلغاء الموقعة، سجل البصمات والتنبيهات (جهاز جديد على Tenant آخر).
كل عملية إصدار/إلغاء باعتماد ثانٍ إذا تجاوزت حدود الخطة (مكافحة خطأ/عبث داخلي).

================================================================================
القسم 5 — الدعم الفني (Tickets)
================================================================================
- تذكرة: رقم تسلسلي، عميل، تصنيف (عطل/سؤال/طلب تطوير/تدريب)، أولوية
  (حرجة P1 النظام متوقف ← P4 استشارة)، وحدة (محاسبة/حجوزات/POS/مزامنة...)،
  قناة (هاتف/واتساب/بريد/من داخل التطبيق)، مرفقات، SLA زمني محسوب من الأولوية.
- سير العمل: جديدة ← مسندة ← قيد المعالجة ← بانتظار العميل ← محلولة ← مغلقة
  (مع تصنيف سبب جذري Root Cause إلزامي للأعطال + مقال معرفة مقترح).
- تصعيد: L1 ← L2 ← هندسة المنتج؛ P1 إشعار فوري لمدير المناوبة (انظر
  SUPPORT_WORKFLOW للتفاصيل والأزمنة).
- قاعدة معرفة داخلية + عامة اختيارية (مقالات حلول متكررة).

================================================================================
القسم 6 — مراقبة صحة العملاء (للهجين/السحابي، وبموافقة تعاقدية)
================================================================================
- نبض: آخر اتصال، نسخة المنتج، صحة المزامنة (تأخر Outbox)، صحة آخر نسخة
  احتياطية، مساحة القرص — مؤشرات خضراء/صفراء/حمراء بلوحة موحدة.
- بياض/تحديثات: إصدار نسخة جديدة ← حلقة تجريبية (Canary: عملاء متطوعون)
  ← تعميم تدريجي ← سجل من حدّث/فشل ولماذا.

================================================================================
القسم 7 — الأمان والتدقيق الخاص باللوحة
================================================================================
- MFA إلزامي لكل مستخدمي الشركة بلا استثناء + IP Allowlist اختيارية.
- أقل امتياز: الدعم لا يرى مفاتيح التوقيع، المالية لا تعدّل تذاكر الدعم...
- Audit مستقل مشفر على كل فعل حساس (إصدار ترخيص، تغيير حالة، فتح تذكرة
  لعميل، تصدير بيانات) — مدقق ربع سنوي (ملف 13).
- Remote Support: وصول الدعم لنظام عميل هجين/سحابي فقط بجلسة مفوَّضة
  زمنياً ومبررة بتذكرة وموافقة العميل المسجلة، وكل الحركات مسجلة وقابلة
  للعرض للعميل (شفافية كاملة = ميزة بيع).

================================================================================
القسم 8 — معايير القبول
================================================================================
1) سداد فاتورة تجديد ← ترخيص جديد يصل العميل (هجين ≤ 5 دقائق؛ محلي: ملف
   فوري) دون تدخل يدوي إضافي.
2) تقرير MRR يطابق مجموع اشتراكات نشطة حسابياً بلا انحراف.
3) تذكرة P1 تولّد إشعار المناوب خلال 60 ثانية.
4) مستخدم دعم لا يستطيع إصدار ترخيص (اختبار RBAC سلبي آلي).
5) كل تغيير حالة اشتراك له سبب + مستخدم + طابع زمني — بلا ثغرة واحدة.
