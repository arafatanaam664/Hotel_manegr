================================================================================
10 — سياسة الأمان الشاملة (Security Policy)
نظام أثير لإدارة الفنادق | الإصدار 1.0 | 2026-08-04
المرجعية: OWASP ASVS L2 كحد أدنى، مبادئ NIST SP 800-53 للضوابط الإدارية
================================================================================

================================================================================
القسم 1 — الحوكمة
================================================================================
- مسؤول أمن معيّن (المؤسس مبدئياً) له حق الفيتو على أي إصدار؛ مراجعة أمنية
  إلزامية لكل ميزة «حساسة» (مالية/هويات/ترخيص/مزامنة) قبل الدمج (Security
  Review Checklist داخل PR).
- سياسة إفصاح مسؤول (security@...) وبرنامج مكافآت ثغرات مرحلة 2.
- تصنيف البيانات: سرية جداً (مفاتيح، هويات، رواتب، تسعير العقود) / سرية
  (مالية العملاء) / داخلية / عامة — كل مستودع بيانات موسوم بفئته.

================================================================================
القسم 2 — المصادقة (Authentication)
================================================================================
- كلمات المرور: ≥ 10 أحمر بفحص تسريبات (قائمة كلمات شائعة محلياً — لا خدمة
  خارجية إلزامية للمحلي)، تخزين Argon2id (أو bcrypt cost≥12)، قفل تدريجي
  بعد 5 محاولات (15 دقيقة ثم مضاعفة)، لا إجابات أمان أبداً (أسئلة سرية ممنوعة)،
  إعادة تعيين بتوكن عشوائي 128-بت صالح 30 دقيقة أحادي الاستخدام.
- MFA: TOTP (RFC 6238) إلزامي للأدوار: مالك/مدير مالي/مشغل ترخيص/دعم الشركة؛
  اختياري لغيرهم مع توصية فرضه لكل من يرى تقارير مالية.
- الجلسات: JWT قصير (15 د) + Refresh معقعّل بالدوران (Rotation) وكشف إعادة
  الاستخدام (Reuse Detection ← إبطال العائلة)؛ المستخدم يرى جلساته النشطة
  ويلغي أيها؛ دخول من جهاز جديد = إشعار.
- سياسة انتهاء: خمول 30 دقيقة للشاشات المالية (POS: PIN سريع لإعادة الدخول
  بدل جلسة كاملة — يقطع طابور العملاء).

================================================================================
القسم 3 — التفويض (RBAC + ضوابط دقيقة)
================================================================================
- النموذج: أدوار ← صلاحيات ذرية (permission strings: hotel.reservation.create,
  accounting.journal.reverse, ...) — لا صلاحية بلا فحص في كل نقطة دخول API
  (Denied by Default).
- الأدوار المزروعة: مالك، مدير عام، مدير مالي، محاسب، مدقق داخلي (قراءة)،
  مشرف استقبال، موظف استقبال، كاشير POS، أمين مخزن، مشتريات، HR، مشرف
  هوسكيبينج، دعم الشركة (مقيد زمنياً/بتذكرة).
- ضوابط فوق RBAC:
  • حدود مالية لكل دور (سقف خصم/سقف إشعار دائن/سقف مرتجع نقدي).
  • فصل الواجبات إجباري (انظر ملف 14): لا اعتماد ذاتي لمستند أنشأته.
  • خصوصية صفية (Row Privacy): رواتب الإدارة العليا، قيود حسابات مخفية.
  • نطاق الفرع: المستخدم يرى فروعه فقط (يُفرض باستعلام لا بالواجهة).

================================================================================
القسم 4 — أمن التطبيق والواجهات
================================================================================
- إدخال: تحقق مخطط صارم (Schema Validation) بكل Endpoint برمجياً؛ لا ثقة
  بأي مدخل؛ Encoding سياقي بالمخرجات (XSS)، CSP صارمة بدون inline scripts،
  إطارات حماية Clickjacking، CSRF Tokens لمسارات الكوكيز.
- ORM فقط لكل استعلام؛ أي SQL خام يمر بمراجعة + Parameters إجبارية.
- رفع الملفات: أنواع مسموحة بيضاء، فحص Magic Bytes، حد حجم، تخزين خارج جذر
  التنفيذ، تقديم عبر Endpoint بموافقة صلاحية (لا روابط مباشرة).
- Rate Limiting + قفل عدائي على تسجيل الدخول ونقاط الحساسة؛ Captcha مرحلة 2.
- أسرار: لا سر بالكود/التاريخ (Gitleaks بالـ CI)؛ أسرار التشغيل بمتغيرات/
  Keystore نظام؛ دوران دوري موثق؛ نسخ الإنتاج مقيدة بأصغر صلاحية DB.

================================================================================
القسم 5 — التشفير وإدارة المفاتيح
================================================================================
- النقل: TLS 1.2+ إلزامي (1.3 مفضل) لكل شيء بما فيه الشبكة المحلية (شهادة
  داخلية مثبتة بالمعالج)؛ HSTS بالسحابي؛ Pinning لقناة الترخيص.
- السكون: أعمدة حساسة مشفرة AES-256-GCM (هويات النزلاء، بيانات موظفين
  المصرفية، مرفقات عقود) + تشفير وسائط النسخ الاحتياطية إلزامياً (ملف
  BACKUP_DISASTER_RECOVERY) + تشفير قرص موصى به بإعداد التثبيت.
- المفاتيح: مفتاح رئيسي لكل Tenant (KEK) يغلف مفاتيح بيانات (DEK) — دوران
  سنوي آلي للـ DEK ويدوي معتمد للـ KEK؛ مفاتيح السحابة بـ KEK في Keystore
  المنصة؛ مفاتيح الترخيص (التوقيع) بوضع Dual Control (ملف 07 §1).
- ممنوع: MD5/SHA1 لأي غرض أمني، DES/3DES، Base64 كـ«تشفير»، مفاتيح ثابتة
  بالكود.

================================================================================
القسم 6 — السجلات والاكتشاف
================================================================================
- Audit Log مقاوم للتلاعب (ملف 13) + سجلات تقنية منظمة بلا أسرار + SIEM
  خفيف سحابي (مرحلة 2) مع تنبيهات: تسجيل دخول شاذ، تصدير ضخم، فشل تحقق
  ترخيص متكرر، تعديل خريطة حسابات، حذف أجهزة.
- البيئة المحلية: سجل محلي مُصدَّر يومياً مع النسخ الاحتياطي (حفظ أدلة
  الطب الشرعي حتى بعزلة تامة).

================================================================================
القسم 7 — أمن النشر والبنية
================================================================================
- سحابي: أقل امتياز شبكي (قاعدة البيانات غير معرضة للإنترنت)، WAF، نسخ
  مشفرة بمنطقة ثانية، خطط ترقيع نظام شهرية، ترقيع طارئ للثغرات الحرجة ≤72 س.
- محلي: معالج التثبيت يطبق Baseline آمن (خدمة بحساب مقيد، جدار حماية داخلي
  يوصى، تعطيل منافذ غير لازمة، كلمة مدير قاعدة قوية عشوائية لكل عميل،
  شهادة TLS داخلية) ويطبع «بطاقة تأمين» يسلمها المنفذ للعميل.
- سلسلة الإمداد: تدقيق تبعيات (SCA) أسبوعي، pinning للإصدارات، بناء متكرر
  (Reproducible Build مرحلة 2)، توقيع حزم التحديث (التحديثات لا تُطبق بلا
  توقيع صالح).

================================================================================
القسم 8 — استجابة الحوادث (مختصر التنفيذ)
================================================================================
سجل حوادث ← احتواء ← تحقيق ← استعادة ← دروس مستفادة خلال 5 أيام عمل
للحوادث الجسيمة؛ خطة إبلاغ عملاء متأثرين خلال 72 ساعة عند مساس ببياناتهم
(بند تعاقدي في SLA — الشفافية ميزة لا عبء).

================================================================================
القسم 9 — اختبارات إلزامية (Building Blocks للـ CI/CD)
================================================================================
- فحص SAST لكل دمج، فحص تبعيات، فحص أسرار، DAST أسبوعي على بيئة staging،
  اختبار RBAC سالب آلي لكل Endpoint حساس، اختبار اختراق سنوي خارجي قبل
  أي إصدار رئيسي (Major) — نتائجه معالجة أولاً بأول.
